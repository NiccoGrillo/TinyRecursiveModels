# PH1 · full-input composition · 27 November 2026

Registered before training or development-outcome inspection. The claim under test is that fresh communication between recurrent slots improves exact composition on unseen pairs of visible operations, at matched learned capacity and arithmetic, because the receiver can use the sender's updated state. This tests an information pathway, not the semantic identity of a slot. This is a diagnostic precursor to interpreting compositions of operations on ARC demonstrations. It is not an ARC score.

## Data, rival and prediction

An input gives four input/output examples defining each of two arbitrary permutations F,G over four symbols, and a one-hot query q. Output G(F(q)). Both slots see all 36 one-hot features. No auxiliary targets, corruptions, selection, demonstration hiding or label-dependent inputs. All four queries for each ordered operation pair stay together. For each G, shuffle the 24 distinct F indices deterministically (PCG64 seed 211); select 16 pairs for training, 4 for development, 4 for held-out characterization. No augmentations. Primary endpoint excludes identity G. Negative control G=identity removes the second lookup, with just four dev groups; interpret descriptively. Example F=(2,0,3,1), G=(1,3,0,2), q=0: first lookup 2, then output 0. An explicit table-lookup baseline should be perfect, a meaningful ceiling because the input already supplies operation boundaries.

Two slots each use their own trained affine full-input encoder and tanh. At each of two recurrent rounds a common update applies tanh(self U + other V + b); role identity is learned by the separate encoders. Dynamic receives the peer's current state. Static receives the peer's initial state both times. Readout uses both final states together. Identical arithmetic, parameter count, precision, batch order, init, training and readout. There is no answer bank or genuine branching policy. A dense recurrent model with structured weights can exactly implement dynamic. If dynamic wins, its incremental gain is over the static-stale-message inductive bias only. At evaluation clamp only round-two messages of trained dynamic to their own task's initial peer states; both recurrent updates and readout still execute. This is an out-of-training-distribution intervention and the separately trained rival is essential.

## Frozen analysis and decision

Train three paired seeds 31, 47, 83 in NumPy float32 on one CPU thread, batch 64, width 32, Adam 0.003, 1500 updates; log train exact/loss every 250. If any arm/seed improves training exact by at least 2 percentage points from 1000 to 1500, extend all to 3000 updates, then stop. Do not read development labels during optimization or tune from results. A fair longer-budget followup remains possible if optimization is inadequate. Primary is mean paired dev exact difference across seeds on nonidentity G, problem group = (F,G), four queries. Resample held-out problem groups jointly across seeds for percentile interval (2000 replicates, RNG 713); show individual seed deltas separately. Keep test partition unopened. Continue this particular mechanism only if gain >=5 percentage points, positive for all 3 seeds and lower 95% group-bootstrap bound >0; changed-state clamp must reduce accuracy. Otherwise park the claim at this budget. Learning insufficiency if both arms under 80% training exact; neither outcome establishes an application win. Record per-query predictions, train curves, gradient/finite-difference checks, source/data fingerprints, full-input equality, batch-one and batch-64 timings and matched MAC counts. Training labels supervise only the final query answer.
